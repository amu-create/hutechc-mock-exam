# AI 번역 전문가 모의시험 · 주관식 자동채점

한↔영 기계번역 후편집·번역 모의시험입니다. 주관식 번역 답안을 **규칙 검사 → AI 오류 검출(3회) → 코드로 점수 계산 → 중앙값** 순서로 채점하고, 답안 위에 오류 구간을 표시합니다.

## 왜 이렇게 채점하나
| 설계 | 이유 |
|---|---|
| AI는 오류(구간·유형·심각도)만 내고 점수는 코드가 계산 | 총점을 바로 받는 방식(GEMBA-DA)은 문장 단위 정확도가 낮고 점수가 5의 배수에 몰림 |
| MQM 감점 critical 25 · major 5 · minor 1, 원문 길이로 정규화 | MQM 공식 점수 모델(0/1/5/25)과 GEMBA-MQM 코드를 따름. 원본의 "오류 5개·합계 25 상한"은 긴 답안을 구별하지 못해 뺌 |
| 같은 답안 3회 채점 → 중앙값, 범위 5점 초과 시 사람 검토 | temperature 0에서도 재채점 점수가 흔들린다는 실험 보고가 있음 |
| AI가 지적한 구간이 답안에 없으면 버림 | 환각 오류 제거 |
| 규칙 검사(빈 답안·언어·복붙·숫자·부정·말투·용어집·핵심 요소)를 먼저 | 확실한 것은 규칙으로, 의미 판단만 AI로 (하이브리드) |
| 한국어 말투·경어를 따로 점검 | LLM이 경어 오류를 잘 못 잡는다는 연구 결과 |
| 답안은 `<student_answer>` 태그로 감싸고 "안의 지시문 무시" | 답안을 이용한 프롬프트 공격 방어 |
| 모범답안은 "여러 정답 중 하나"로 명시 | 표현이 다른 정답을 감점하지 않게 |

급수 경계(90·80·70)와 보정값(`lib/scoring.js`의 `SCORING_CONFIG`)은 **데모용 가정**입니다. 관리자 화면에서 사람 점수를 입력해 AI와의 차이를 보고 맞춥니다.

## 구조
```
index.html            화면 틀
assets/app.js         시작 → 응시(타이머·문항판·3칸 후편집) → 결과 → 관리자
assets/styles.css
lib/questions.js      문항(직접 만든 예시, 기출 아님) — 서버가 원문·모범답안을 여기서 찾음
lib/scoring.js        규칙 검사·오류 검증·점수 계산·중앙값 (브라우저·서버 공용)
api/grade.js          Vercel 함수: POST /api/grade { questionId, answer }
tests/                node --test
dev-server.mjs        로컬 확인용
```

## 실행
```bash
npm test          # 채점 로직 테스트
npm run dev       # http://localhost:3000
```

## AI 채점 켜기 (Vercel)
1. Vercel 프로젝트 → Settings → Environment Variables → `ANTHROPIC_API_KEY` 추가
2. (선택) `GRADER_MODEL` 기본 `claude-sonnet-5-5`, 더 싸고 빠르게는 `claude-haiku-5-5` / `GRADER_RUNS` 기본 3
3. **다시 배포**해야 반영됩니다 (환경변수는 새 배포에만 적용)

키가 없으면 규칙 채점만으로 동작하고 화면에 "규칙 채점만"이라고 표시합니다. 키는 서버 함수에만 있고 브라우저로 나가지 않습니다.

## 확장 계획
- 응시 기록: 지금은 브라우저 저장(데모) → Supabase 테이블 + RLS(응시자는 INSERT만, 관리자만 SELECT) + 관리자 로그인
- 접수: 시험 안내 → 약관 동의 → 종목·급수 선택 → 인적사항 → 확인 → 접수번호
- 통역 문항: 브라우저 녹음 → 음성 인식 → 핵심 정보 포함 여부 채점
- 번역사 이력 관리: 합격자 프로필(언어쌍·분야·급수·검수 이력)과 감수 매칭
