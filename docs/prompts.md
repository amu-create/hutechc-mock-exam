# 실습 현장 프롬프트 (붙여 넣기용)

리포: https://github.com/amu-create/hutechc-mock-exam · 배포: https://hutechc-mock-exam.vercel.app
사용법: [ ] 부분만 현장 과제에 맞게 바꿔서 Claude 클라우드 세션(claude.ai/code)에 붙여 넣는다. Codex에는 0번만 쓴다.

## 공통 머리말 (모든 프롬프트 맨 앞에)
```
이 리포는 번역·통번역 자격시험 회사용 모의시험 + 주관식 번역 자동채점 데모다.
README의 "왜 이렇게 채점하나" 표가 설계 원칙이다. 이 원칙은 지킨다:
- AI는 오류 목록만 내고 점수는 lib/scoring.js 코드가 계산한다
- API 키는 api/ 서버 함수에만 둔다(브라우저 코드에 키·비밀값 금지)
- 화면에 넣는 사용자 입력은 esc()로 감싼다
작업 순서: 기존 구조를 먼저 읽고 → 바꿀 파일 목록을 3줄로 말하고 → 작게 고친다.
끝나면 npm test 통과, main에 커밋·푸시까지 하고, 바뀐 화면과 확인 방법을 3줄로 보고한다.
면접 시연용이라 시간이 짧다. 요청에 없는 리팩터링·의존성 추가는 하지 않는다.
```

## ① 모의시험 확장 (과제가 시험·교육·채점 쪽일 때)
```
[공통 머리말]
과제: [면접관이 준 과제 한두 문장 그대로]
이 과제를 기존 모의시험 앱 위에 얹어라. 새 문항이 필요하면 lib/questions.js에 같은 형식(원문·번역기 출력·모범답안·용어집·keypoints)으로 추가한다.
완료 기준: 홈 → 응시 → 제출 → 결과에서 새 기능이 보이고, 결과 화면의 오류 하이라이트와 관리자 표가 깨지지 않는다.
실패로 보는 것: 점수를 AI가 직접 매기게 바꾸는 것, 기존 6문항 흐름이 깨지는 것, 모바일(390px)에서 가로 스크롤이 생기는 것.
```

## ② 시험 접수(신청 폼) + 관리자 목록
```
[공통 머리말]
과제: 시험·교육과정 접수 화면을 추가한다. 새 해시 경로 #/apply 와 #/admin/apply 를 만든다.
흐름: 안내(일정·응시료·환불 규정) → 약관·개인정보 동의(전체 동의 포함) → 종목(번역/통역/프롬프트) → 급수 선택(종목에 따라 바뀜) → 이름·연락처·이메일 → 입력 확인 → 접수번호가 있는 완료 화면.
저장: 지금은 기존처럼 브라우저 저장. 함수 하나(saveApplication/loadApplications)로 감싸서 나중에 DB로 바꾸기 쉽게 한다.
관리자: 접수번호·이름·종목·급수·신청일·상태(접수/확인/취소) 표, 종목·상태 필터, 상태 변경, CSV 다운로드.
실패로 보는 것: 동의 없이 제출되는 것, 필수 입력 검증 없음, 모바일에서 폼이 잘리는 것.
```

## ③ 번역사(전문가) 이력 관리
```
[공통 머리말]
과제: 시험 합격자를 번역·감수 인력으로 관리하는 화면을 추가한다. 새 해시 경로 #/experts.
목록: 출발어→도착어 언어쌍 검색, 분야(법률·IT·마케팅·의료)·급수·응대 가능 필터, 카드(이름·한 줄 소개·언어쌍 배지·분야 태그·급수 배지·검수 건수·평균 품질 점수).
상세: 모국어, 분야, 경력, 단가(단어당), 자격(모의시험 급수 자동 표시), 검수 이력 표, 품질 점수 추이(간단한 막대).
시드 데이터 12명은 lib/experts.js에 만든다(실존 인물 이름 금지).
연결: 모의시험 결과 화면의 급수가 "합격"이면 [전문가 등록 신청] 버튼으로 #/experts 신규 등록 폼으로 간다.
실패로 보는 것: 필터가 동작하지 않는 것, 빈 화면, 모바일 카드 깨짐.
```
